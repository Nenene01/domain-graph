# エージェント運用

このディレクトリは、Domain Graph の開発で使うエージェントの責務と連携手順を定義します。Orca上では、PMを常設の調整役とし、Terraが設計・実装指示を作り、Lunaが実装します。Solは必要なIssueだけをレビューします。

## 基本フロー

1. PMがPLAN.mdとGitHub Issueを読み、依存関係から次の作業を1〜2件選ぶ
2. Terraが対象Issueの設計、変更範囲、テスト方針、リスクを整理する
3. PMがTerraの指示を受け入れ、Lunaへ実装タスクを渡す
4. Lunaが実装・テストし、Issueとコミットに結果を記録する
5. PMが受け入れ条件を確認する
6. リスクが高い変更や判断が割れる変更だけSolにレビューさせる

## レート制限対策

- エージェントを常時大量起動せず、依存関係に基づく小さなready waveで進める
- Terraの設計指示、Lunaの実装結果、Solのレビュー結果を再利用し、同じ調査を繰り返さない
- 1回の作業単位をIssue単位に固定し、無関係な探索を依頼しない
- テスト・レビューは差分中心に行い、リポジトリ全体の再読込を避ける
- 失敗時は同じ作業を即時重複起動せず、ログと状態を確認してから再試行する
- まとまった成果が出た時点でcommit/pushし、進捗をIssueへ記録する

## 完了条件

PMは、対象Issueの受け入れ条件、テスト結果、出所・根拠、変更ファイル、未解決事項を確認してから完了扱いにします。削除や破壊的な履歴変更は自動実行しません。
